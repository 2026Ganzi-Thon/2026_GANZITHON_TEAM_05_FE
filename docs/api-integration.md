# API 연동 상태

2026-11-19 기준. 프런트 브랜치: `feat/api-integration`.

기준 자료는 전달받은 「Letit API 상세 명세서 v1.0 (26개 · 프론트 공유용)」 PDF와 백엔드 저장소의 실제 OpenAPI·스키마입니다. PDF의 지침은 계약을 이해하는 참고 자료로 사용했고, 카카오맵 전환과 위치 권한 요청은 사용자가 별도로 승인한 범위입니다.

## 구현과 확인 범위

프런트의 26개 요청은 `src/api/endpoints.ts`에 모았습니다. API 모드에서는 성공 데이터를 목업으로 대체하지 않습니다. 아래의 '명세 재현'은 서버 구현 완료를 뜻하지 않습니다.

| 기능                                                            | API 수 | 프런트 | 검증 방법                                  |
| --------------------------------------------------------------- | -----: | ------ | ------------------------------------------ |
| 회원가입·로그인                                                 |      2 | 연결   | 로컬 실제 FastAPI + 브라우저               |
| 기본값 조회·저장                                                |      2 | 연결   | 로컬 실제 FastAPI + 브라우저               |
| 추천·생성·상세·체크·중간 저장·완료·이어하기·재개·중단·대체·교체 |     11 | 연결   | 명세 재현 응답 + 브라우저                  |
| 주변 장소 검색                                                  |      1 | 연결   | 명세 재현 응답 + GPS 허용/거부 + 지도 선택 |
| 휴식·후기·성찰 3종·아카이브 3종                                 |      8 | 연결   | 명세 재현 응답 + 브라우저                  |
| 도감 조회·꽃 확인                                               |      2 | 연결   | 명세 재현 응답 + 브라우저                  |

확인한 백엔드 `main`에는 4개 API만 등록되어 있으며 다른 원격 브랜치와 열린 PR은 없습니다. 나머지 22개는 서버 구현 후 실제 데이터로 다시 검증해야 합니다. Supabase·AI·Kakao Local REST API의 외부 연동은 현재 백엔드에 없습니다. 로컬 검증에서는 별도의 SQLite 테스트 DB와 합성 계정을 사용했습니다. 공동 DB·실사용자 기록은 변경하지 않았습니다.

## 동작 규칙

- `VITE_API_BASE_URL`이 비어 있으면 기존 메모리 목업 모드입니다. 값이 있으면 API 모드로 실행하고 `/api/v1`은 중복해서 붙이지 않습니다.
- 인증 토큰은 메모리에서만 보관합니다. 명세에 refresh API가 없어 새로고침하면 재로그인합니다. 비밀번호·기분·후기·위치를 브라우저 저장소나 로그에 남기지 않습니다.
- 로그인 후 `GET /users/me/defaults`의 `onboardingCompleted`로 설문과 홈을 구분합니다. 설문 저장 실패 시 선택을 유지합니다. 계정 변경·만료 시 초안과 쿼리 캐시를 정리합니다.
- 단계는 `order`로 표시하고 `stepId` UUID 배열로 PATCH합니다. 연속 체크를 직렬화하고 저장·완료는 마지막 체크 요청을 기다립니다. POST·PUT·PATCH·DELETE는 자동 재시도하지 않습니다.
- 생성·교체 POST 후 상세 GET이 실패한 경우 받은 미션 ID로 상세만 재조회합니다. 상세 조회 실패를 이유로 같은 생성 POST를 다시 보내지 않습니다.
- 온보딩 기본값은 별도 유지합니다. 같은 실행 중에는 직전 외출의 에너지·거리·시간·예산을 재사용하고 기분·장벽은 초기화합니다.
- 장소 없는 미션은 GPS와 주변 검색을 생략합니다. 장소 미션에서 동의 버튼을 누른 뒤 GPS를 요청합니다. 거절·오류·검색 결과 없음에 재시도와 다른 미션 선택을 제공합니다.
- 주변 검색은 `placeCategory`와 에너지별 반경을 전달합니다. 장소 선택은 명세대로 카카오 `placeId` 문자열만 보냅니다. 이동 시간은 `약 N분 (추정)`입니다.
- 달력·통계·꽃은 서버 조회 결과를 표시합니다. 아카이브 삭제는 서버의 숨김 처리만 요청합니다. `claim`은 서버가 지급한 꽃을 확인하는 요청이며 클라이언트에서 지급 일수나 꽃을 생성하지 않습니다.
- 키는 `.env.local`에만 설정합니다. `.env.example`에 빈 항목을 공유합니다. `VITE_KAKAO_MAP_APP_KEY`에는 공개 JavaScript 키만 사용합니다.

## 백엔드에서 확정할 항목

1. **나머지 22개 구현과 실제 서버 주소/CORS**: 현재 원격 백엔드는 인증·기본값 외에 404를 반환합니다.
2. **장소 스냅샷**: 생성·교체 요청은 `placeId`만 전송합니다. 서버가 검색 결과를 사용자별로 보관하거나 ID로 재조회해 장소 이름·주소·좌표를 복원해야 합니다.
3. **잘린 PDF 응답 필드**: 성찰 `completedByEnergy`의 개별 항목과 거리 변화 배열의 정확한 키·구조가 필요합니다. 현재 어댑터는 `{energyLevel,count}` 또는 `{energyLevel,completedCount}`, 거리 배열은 `distanceChanges` 또는 `distanceHistory`의 `{date,distanceMeters}`를 처리합니다. `firstMission/latestMission`은 `{title,date}` 또는 `{title,startedAt}`를 처리합니다. 실제 OpenAPI를 받으면 `contracts.ts`와 어댑터를 확정해야 합니다.
4. **예비 추천 표시**: PDF에는 예비 데이터 표시 정책이 있지만 구분 필드는 없습니다. 현재 `fallback: true`를 지원합니다. 서버 필드명 확정이 필요합니다.
5. **재로그인 후 직전 조건**: 명세에는 온보딩 기본값 API만 있습니다. 직전 외출 조건을 앱 재실행 이후에도 복원하려면 별도 서버 필드나 조회 경로가 필요합니다. 브라우저 영구 저장으로 대신하지 않았습니다.
6. **꽃 번호와 에셋**: `flowerNumber` 1~18을 Figma 에셋 번호와 동일하게 사용해야 합니다. 이름·설명은 API 응답을 표시합니다. 자동 지급의 중복 방지와 이미 얻은 꽃 유지 정책은 서버에서 보장해야 합니다.
7. **중복 변경 방지**: 통신 단절 시 POST 성공 여부를 판별할 수 없는 경우를 위해 생성·교체·완료의 서버 중복 방지 정책이 필요합니다. 프런트는 변경 요청을 자동 재전송하지 않습니다.

## 로컬 검증 재현

```bash
npm test
npm run lint
npm run build
npm run format:check
```

`npm test`는 Node 기본 테스트 러너와 Vite의 TS 로더를 사용합니다. 실제 외부 서버·키 없이 26개 메서드/경로/본문/Bearer 헤더, UUID 단계, 요청 순서, 로그인 401과 세션 만료 구분, 타임아웃·취소·응답 검증, 조건 단위 변환을 검사합니다.

브라우저 검증은 로컬 실제 인증 4개와 명세 재현 응답 22개를 구분해 수행했습니다. 실제 가입·설문·재로그인, 빠른 체크·완료·후기 실패 후 재시도·꽃 확인, 위치 거부·빈 장소·지도 선택, 부분 저장·재개·중단, 대체 미션, 아카이브 페이지 추가·상세·숨김 삭제, 성찰 월 이동, 320/402/1280px 화면을 확인했습니다. 카카오 SDK의 실제 인증·타일 로딩은 허용 도메인 등록 후 별도 확인합니다.

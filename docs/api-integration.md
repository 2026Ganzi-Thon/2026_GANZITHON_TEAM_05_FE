# API 연동 상태

2026-11-20 기준. 프런트 PR: [#6](https://github.com/2026Ganzi-Thon/2026_GANZITHON_TEAM_05_FE/pull/6).

전달받은 26개 API 명세와 백엔드 실제 응답을 기준으로 인증·기본값·추천·미션·후기·성찰·아카이브·도감을 연결했습니다. 모든 요청은 `src/api/endpoints.ts`에 모았고 화면 이벤트 또는 조회 훅에서 호출합니다. API 모드의 실패를 목업 성공 데이터로 대체하지 않습니다.

## 실행 설정

- `VITE_API_BASE_URL`: 백엔드 origin 또는 `/api/v1`까지의 URL. 비어 있으면 기존 메모리 목업 미리보기입니다.
- `VITE_KAKAO_MAP_APP_KEY`: 공개 JavaScript 키. Kakao Developers의 JavaScript SDK 허용 도메인 등록과 카카오맵 사용 설정이 필요합니다. REST 키는 백엔드에만 설정합니다.
- 개인 `.env.local`, 키, SQLite 파일은 커밋하지 않습니다. 인증 토큰과 화면 상태는 메모리에만 보관하므로 새로고침하면 재로그인이 필요합니다. 비밀번호·후기·위치는 브라우저 영구 저장소나 로그에 남기지 않습니다.
- 로컬 통합 미리보기는 별도 백엔드 `8001`과 프런트 `5178`을 사용합니다. 이 설정은 공유 배포 서버 주소가 아닙니다.

## 프런트 처리

- 로그인 후 기본값의 `onboardingCompleted`로 설문과 홈을 구분합니다. 계정 변경·세션 만료 시 상태와 쿼리 캐시를 정리합니다.
- 단계 체크는 UUID `stepId`로 직렬 저장하고, 저장·완료는 마지막 체크 요청을 기다립니다. 변경 POST는 실패 시 자동 재전송하지 않습니다. 생성 후 상세 조회 재시도는 생성 요청을 반복하지 않습니다.
- 서버의 `fallbackUsed`, 상황 enum, 단계 개수가 생략된 응답, 이어하기 목록의 누락 필드를 처리합니다. 장소 상세가 ID만 제공되면 같은 실행의 검색 결과로 보완하고, 없으면 정보 없음으로 표시합니다.
- 종료일 `null`과 시간대 없는 UTC 시각을 처리합니다. 홈의 미션 건수와 성찰의 날짜별 일수를 구분합니다. 꽃 지급은 서버가 결정하고 프런트의 `claim`은 확인만 요청합니다.
- 장소 미션을 선택하면 브라우저의 기존 위치 권한을 먼저 조회합니다. 이미 허용했다면 앱 동의 팝업 없이 검색하고, 미결정·거부 상태라면 안내를 표시합니다. 권한 조회를 지원하지 않는 브라우저에서는 현재 로그인 세션의 동의를 재사용합니다. 새 미션을 시작해도 세션 동의는 유지하고 계정 초기화 시 지웁니다. 위치 좌표는 장소 미션 선택·동의 이후에만 요청합니다.
- 재검색 때는 이전 좌표를 재사용하지 않고 고정밀 위치를 새로 요청합니다. 기기가 알려준 오차가 검색 반경보다 크면 화면에 안내합니다.
- 기획의 검색 반경인 1단계 50m·2단계 100m·3단계 500m를 유지합니다. 4단계는 거리 조건을 사용합니다. 반경을 화면에 표시하고 빈 결과에는 위치 재검색·조건 변경·다른 미션 선택을 제공합니다. 결과가 없다고 범위를 자동 확대하지 않습니다.
- 실제 Kakao Local 결과를 지도와 카드에 표시하고 선택을 동기화합니다. 여러 장소는 두 열로 배치해 402px 앱 너비를 유지하며 본문에서 세로 스크롤합니다. 화면 크기가 바뀌면 지도 범위를 다시 맞춥니다. 도보 시간에는 추정 표시를 사용합니다.

## 검증

- 프런트 자동 테스트 18개 통과: 26개 요청 계약, 단계 저장 순서, 401·실패·취소·타임아웃, 응답 보완, 날짜·집계·꽃 확인, 위치 재요청·권한 거부, 기존 권한 조회·철회·미지원 처리와 동의 초기화.
- 위치 권한이 이미 허용된 브라우저에서 재선택·새 미션·새로고침/재로그인 후 동의 팝업을 생략하는 것을 확인했습니다. 첫 동의 전 위치 요청 0회, 동의 후 검색, 권한 철회 시 재확인을 별도로 브라우저 검증했습니다.
- 타입 검사·린트·Prettier·프로덕션 빌드·diff 검사 통과. 빌드에는 기존 번들 크기 경고가 있습니다.
- 사용자 승인 범위에서 백엔드 두 PR을 **로컬에서만 통합**하고 별도 SQLite DB와 합성 계정으로 26개 API를 37회 성공 호출했습니다. 실제 Kakao Local 검색을 사용했고 Upstage 키가 없어 AI는 서버 예비 추천으로 확인했습니다.
- 실제 로컬 통합 서버를 사용한 브라우저 흐름 69회 요청 성공, API 응답 가로채기·브라우저 오류·실패 응답 0건. 가입·설문·휴식·추천·위치 동의·장소 선택·중간 저장·이어하기·완료·후기·꽃 확인·도감·성찰·아카이브 숨김을 확인했습니다.
- 실제 카카오 검색의 15개 결과와 1·2·15개 합성 목록을 320/402/1280px에서 확인했습니다. 장소 카드 가로 넘침 없음, 핀 선택 동기화, 동의 전 위치 요청 0회, 재검색 시 새 좌표 사용, 50m 안 편의점 결과 없음·오차 안내·조건 변경을 확인했습니다. 테스트에는 공개 시청 좌표를 사용했습니다.

## 공유 백엔드와 남은 확인

[백엔드 PR #1](https://github.com/2026Ganzi-Thon/2026_GANZITHON_TEAM_05_BE/pull/1)과 [PR #2](https://github.com/2026Ganzi-Thon/2026_GANZITHON_TEAM_05_BE/pull/2)가 모두 백엔드 main에 병합됐습니다(병합 커밋 `2611ef5`). PR #2는 프런트에서 읽고 비교한 `31e0457` 그대로 병합됐으며, 모든 라우터 등록과 미션 완료→기록·꽃 갱신 연결을 포함합니다. 병합된 백엔드 main을 직접 실행한 검증은 아직 하지 않았습니다. 프런트 작업으로 백엔드 원격에 push·merge하지 않았습니다.

로컬 통합 서버에는 장소 검색 결과 보관·미션 장소 스냅샷 저장, 기록·꽃 갱신, 에너지 0단계 실내 예비 미션 보완이 포함돼 있습니다. **로컬에서 전체 흐름이 통과한 결과가 공유 백엔드의 같은 동작을 보증하지는 않습니다.** 서버 담당자는 백엔드 main에 같은 처리가 있는지, 장소 스냅샷·0단계 추천·날짜별 집계가 실제 배포 서버에서도 동작하는지 확인해야 합니다.

실제 Upstage AI, Supabase, 공유 배포 서버의 주소·CORS는 미검증입니다. 배포된 백엔드 주소는 아직 없어 프런트 배포(`https://letit.vercel.app`)는 목업 모드로 동작합니다. 백엔드 기본 CORS는 `http://localhost:5173`만 허용하므로 배포 시 `CORS_ORIGINS`에 프런트 배포 주소를 추가해야 합니다. 직전 외출 조건의 재로그인 후 복원은 별도 서버 계약이 필요합니다. 생성·교체·완료의 통신 단절 후 중복 방지는 서버 정책이 필요하며 프런트는 변경 요청을 자동 재전송하지 않습니다.
